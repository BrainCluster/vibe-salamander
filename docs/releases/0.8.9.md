## New

- **Cloud files stay in the cloud.** Files that OneDrive, iCloud or Dropbox keep only online are downloaded only
  when you open, view, copy or move one. Tools that just look leave them alone: Find with text or inside ZIP files,
  Find Duplicates, Compare Directories by content, quick view, thumbnails, program icons, and checksums of a
  marked folder. Each says how many files it didn't read. To read them too: the **Cloud-only files** box in Find
  and Find Duplicates, and "Also compare files that are only in the cloud" in Compare Directories.
- The **Attr column** shows O for a file that is only in the cloud, P for one always kept on this device and U for
  one whose space may be freed, as Windows' `attrib` does.

## Fixed

- **Copy or move onto the same file through another path** (a junction, a hard link, a `subst` drive): the file
  was offered for overwriting, and a move could then have deleted it. It is now recognized as the same file and
  refused, like copying a file onto itself.
- **A folder copied or moved into a link that leads inside it** was copied into itself.
- **Verify copies**: a copy that differed from its original stayed in the target, and Retry failed on it. The bad
  copy is now removed, and Retry copies again.
- **Translations**: Windows Explorer, Temp, Recent and Startup were English in some languages.

## Under the hood

- Tests for the copy engine's dangerous cases: every answer to "the target exists" for copies and moves, sources
  that disappear, locked targets, failed verification, links and hard links.
- A test keeps the eleven translations complete: a text without a translation fails the build.
- The UI tests wait until the program says it is ready instead of guessing how long a slow machine takes.
- Speed is measured in every build (listing, sorting, searching, copying, large text files, start time, memory).
